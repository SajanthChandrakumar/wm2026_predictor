# UCL 2026/27 Competition Support

## Goal

Extend the existing WM 2026 predictor with a competition-aware UCL 2026/27 mode while preserving the current WC behavior and API compatibility. The UI defaults to UCL; API calls without a competition remain WC. Never spend provider credits from public refresh routes and never fabricate missing ratings or historical odds.

## Global constraints

- Competition IDs are exactly `wc2026` and `ucl2026`.
- Existing API requests without a competition resolve to `wc2026`; the frontend initially selects `ucl2026` and persists the selection locally.
- Existing scoring stays 5 tendency + 1 per exact team-goal + 3 goal difference when tendency is correct; knockout games double the result.
- Model and pool tips freeze at T-15 minutes; public user tips close at T-5 minutes.
- Odds collection buckets are T-24h, T-6h, T-75m, T-30m and T-15m. One maintenance invocation makes at most one Odds API bulk call per competition.
- Odds snapshots are append-only and later observations must never masquerade as earlier snapshots.
- `is_ko` is accepted only as a legacy WC fallback. New predictions derive stage, leg and extra-time eligibility from stored match metadata.
- No silent 1500/1650 rating fallback. Odds-only and Elo-only modes are explicit; neither source means `unavailable`.
- Preserve the existing dirty files in the user's main checkout. Do not modify `data/elo_history.json`, `data/elo_ratings.csv` or `fotos for wm /`.
- Use TDD for production behavior. No live-provider calls in tests.
- Do not dispatch subagents from worker tasks. Each worker commits only its scoped changes and writes the requested report.

## Task 1: Competition core and storage isolation

Introduce a minimal competition registry for `wc2026` and `ucl2026` containing display metadata, ESPN slug, Odds API sport key, season, ruleset and Mongo collection names. Add competition parsing/defaulting and make archive RAM caches collection-aware. Namespace cache/state/custom-bot documents and expose `GET /api/competitions`. Add optional `competition` to existing read/write routes while retaining WC defaults and legacy response fields. Add focused tests proving unknown IDs return 400, omitted IDs mean WC, archives/caches do not leak across competitions, and existing WC contracts still work.

## Task 2: UCL providers, snapshots and protected maintenance

Make ESPN and Odds provider identifiers configurable. For UCL, fetch ESPN date windows in bounded chunks and deduplicate by event ID. Add ClubElo ingestion using the ranking page/cache contract with alias mapping and provenance; use odds-only or Elo-only explicitly when one source is absent. Add append-only odds snapshots and bucket state. Implement `POST /api/internal/maintenance` protected by constant-time Bearer `CRON_SECRET` comparison, a Mongo lease/unique claim, due-bucket detection and no more than one `h2h,totals` bulk call per competition/run. Public `force=true` must never call providers or mutate data. Tests use complete captured/fake provider responses and cover authorization, idempotency, missed buckets, T-15 input selection, provider failure states and credit caps.

## Task 3: Central prediction, pool strategy and extra time

Create one prediction service used by matches, predict, freeze and reconstruction. Return `model_tip`/legacy `top_tip`, `pool_tip`, score matrix, xG, source mode, model version and input provenance. Introduce match context fields `stage`, `tie_id`, `leg`, first-leg score, `score_90`, `score_aet`, shootout winner and extra-time eligibility. Build AET distributions by leaving non-trigger 90-minute cells unchanged and convolving only trigger cells with independent 30-minute Poisson increments using xG/3. Penalties choose advancement 50/50 but never alter SRF scoring. Implement manual field tip counts and `pool_tip = argmax(E[advantage] + lambda * SD[advantage])`, where advantage is candidate points minus average opponent points and `lambda = min(0.6, 0.6 * max(0, leader_points-user_points) / max(1, remaining_srf_max_points))`. Missing/invalid field counts make only the pool tip unavailable. Enforce T-15 model/pool freeze and T-5 user-tip closure. Add red-green tests for every rule and retain WC scoring.

## Task 4: UCL league table and full tournament simulation

Add a UCL table engine validating 36 teams, 144 league matches, eight matches and four home/four away per team. Rank using points, goal difference, goals, away goals, wins, away wins, opponents' points, opponents' goal difference, opponents' goals, disciplinary score and a versioned UEFA coefficient rank; live display prefers ESPN's official order, simulations use the local engine with future discipline tied. Build a deterministic seeded 20,000-run simulator fixing known results and sampling open match score matrices, then following the official position-pair playoff/R16 path, two-leg aggregate rules and single-leg final. Return expected points/rank and Top-8, Top-24, R16, QF, SF, final and champion probabilities. Keep the existing WC simulator behavior. Tests cover invariants, all ranking stages, bracket/home-leg mapping, ET/penalties and reproducibility.

## Task 5: Competition-aware frontend and all views

Add a WC/UCL selector backed by the competition endpoint. Scope all API calls, React Query keys, invalidations, selections, archives, bots and performance data by competition. Remove the global KO toggle for new match data. Make Dashboard, Value Bets, Edge, Team Form, Performance/Build-a-Bot and Simulator competition-aware. Show the 36-team UCL league table instead of WM groups and render the full UCL simulator outputs. Add manual pool-context editing and show separate model/pool tips and data-status/provenance. Add team-logo fields with a safe text fallback and narrow CSP support. Preserve WC routes/views. Typecheck, lint source, and build; do not commit generated `dist` until Task 6.

Protect existing maintenance-style mutation endpoints consistently. Normalize failure payloads to `fresh`, `stale`, `unavailable` or `failed` with source and timestamps. Update documentation and CI to run Python tests plus frontend typecheck/lint/build. Rebuild and commit tracked `frontend-v2/dist`.
